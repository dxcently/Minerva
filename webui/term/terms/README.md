# webui/term/terms

The web terminals' side of the page: the ⌨ tab in the right panel, one xterm per terminal, the agent's activity while the tab is not showing,
and the terminal panes (T4b). The shells live in the perch (`perch/src/term/README.md`); this folder draws them and sends what is typed.

| `model.js` | the roster (metadata only, from `GET /hub/term` and the stream), the one terminal stream (`/hub/term/events`, opened while a view shows, closed 10 s after the last; a connection's frames stop at its abort, a resync makes its entry stale until the reset, a connection that ends mid-reset forgets that reset's seq, and reconnects wait at least `MIN_WAIT`), each terminal's input (one POST in flight, raw `application/octet-stream`, never retried, never in the lane), a person's refresh (`refreshNow`, one `hubGet`) and the activity poll (`pollNow`, through the lane), and the pure helpers: `vet`, `rankRows`, `foldDefault`, `diffRoster`, `inputQueue`, `decodeB64`, `clipText`, `refusalWords`, `sinceOf` |

## The contract (what T4b and later read)

- `mountTerm(id, el)` / `unmountTerm(id, el)`: a terminal's one element goes into `el` (a stack item's clip, or a pane's host) and back to the shelf. A second mount moves it; `unmountTerm` leaves it alone when `el` is no longer the host.
- `screenOf(id)` is the xterm for a terminal (null until its module is in); `mountedIn(id)` is the host element now showing it.
- `watch()` opens the stream for one view and returns the function that gives the view back (a pane counts as a view).
- `roster`, `status`, `live`, `typed(id, bytes)`, `bell`, `setHold`: the signals and the input path. The input queue's `busy` getter (`inputQueue`, model.js) is the in-flight flag: one call at a time, the rest wait in order.
- `makeScreens()`: the tab calls it on mount, and it makes a screen for each terminal the page holds. A screen is made only while the tab is drawn or a host shows the terminal (`view.js` `ensure`), so the module does not load at page boot.
- `refreshNow()`: a person's refresh, one `hubGet` of the roster, applied only while the stream is closed. The poll (`pollNow`) is the lane's and is not used for a person's action.
- `term-out` chunks of a reset: `onFrame` passes `cont` to the screen's `out` hook when a term-out's seq is the page's already (the reset's seq, which the perch gives each of its chunks, perch/src/term/README.md "The stream"). `push` counts neither a reset nor those chunks against `BACKLOG_MAX`.
- A terminal pane is an xpane of kind `term` whose data names the terminal as `term`: `host.openXPane('term', { term: 't4' })`. (`openXPane` spreads its data and then sets `id` to the pane's own, so the terminal's id is not kept under `id`.) The stack finds the pane by that pair (`paneOf` in tab.js).
- The stream's frames are in `perch/src/term/README.md` ("The stream"). The routes used: `GET /hub/term`, `POST /hub/term` (`{chat}` or `{}`), `POST /hub/term/<t>/input` (raw bytes), `POST /hub/term/<t>/hold` (`{hold}`), `GET /hub/term/events?since=`.

## Decisions applied (BRIEF and WAVE3)

- D11: the terminals use the system mono (`"Cascadia Mono", Consolas, monospace`), not the page's font. The terminal stream takes one of the four connection slots (`extraStreams`), so the chats get three, and it opens only when a slot is free ("terminals need a stream slot"). With the ⌨ tab not showing, a focused chat's agent opening a terminal switches the rail to ⌨ once per terminal and never moves the keyboard focus.
- The xterm link handler is set on every terminal: an OSC 8 link is opened only when it is http or https, on ctrl+click, with `noopener`. No clipboard addon is vendored, and no `window.open` is reached for another scheme.
- Queries: the page swallows the perch's answers (DA1, DA2, DSR 5 and 6, DECRQM, CSI 18 t, OSC 4, 10, 11 and 12 asking) and also DECRQSS and XTVERSION, which the perch never answers. So neither side replies to those two: a program that asks gets no answer, never two. The orchestrator accepted this (no reply beats one reply from every open page), and `perch/src/term/README.md` now says the same.
  - xterm answers more DSR forms than the perch does: `CSI 6;1 n` (xterm reads params[0] only) and the private `CSI ? 6 n` (DECXCPR). Each reply would be typed into the terminal as operator input, so DSR matches xterm's own params[0] switch and a `DSR DEC` entry (`{ prefix: '?', final: 'n' }`) takes the private form. The private entry also takes `CSI ? 5 n`, which xterm does not answer; swallowing it costs nothing.
  - A test runs the real vendored xterm headless (it loads under node, and `write` with a callback parses without `open`): every form in the list, with `onData` silent; a second test shows xterm does answer the DSR forms without the page's queries.
- Input: the perch refuses anything but `application/octet-stream` (415), so the page posts raw bytes with the one `fetch` in `model.js`, with `auth()` from `core/api.js`. `hubPost` sends JSON and cannot carry it.
- `[ new terminal ]` sends `{chat}` only, so the perch takes the chat's remembered folder (never checked against its roots, as the perch documents). An explicit folder is root-checked by the perch, so the page does not send one. `in folder…` opens the `:` line with `term ` (T4b's `:term` must take a folder for this to finish).
- Screens are made for the tab, not at boot: `ensure` makes one only when the tab is drawn (`tabShown`) or a host shows the terminal, and `makeScreens` (the tab's mount) makes the rest. Until then a terminal's bytes queue under the 2 MB bound, as before a screen exists. Folded terminals keep their screens on the shelf (`.tpark`: laid out, `visibility: hidden`, off-screen, not `display: none`), because xterm measures a screen that has layout and a fold is a view choice: a folded terminal's screen keeps taking the output the stream brings while it is open, so opening it again shows the live screen, not a replay.
- No fit addon: the screen takes the perch's size (the roster row, then `term-size`) and the page never fits it to an element, so `vendor/addon-fit.js` is not loaded. It stays vendored (`vendor.test.mjs` pins it) for a slice that needs it.
- A reset over 32 KiB is `term-reset` and then `term-out` chunks, each at the reset's seq (perch/src/term/README.md, "The stream"). A term-out whose seq is the page's already is one of those chunks, and it is counted as the reset's bytes, not as backlog. The bound stays at 2 MiB (`BACKLOG_MAX`). Raising it to the ring's 8 MiB (`RING_MAX`, pty.rs:53) was the other option; it would have loosened the guard for all live output four-fold, to cover a case the frames already mark. A test drives a reset with 3 MiB of chunks (no resync) and live output past 2 MiB (resync).
- The foreground name is text like the title: `vet` and the `term-title` frame cut it to `TITLE_MAX` (80 characters) with controls and bidi marks removed, and the header shows the title, else the foreground, else the id.
- The risk line (under the tab's bar) states the three risks an agent's terminal tools expose: a read of any web terminal, the operator's included, sends its screen to the model provider; that text is untrusted and unfiltered; in yolo agents type without asking. The section it follows, "What an agent's terminal tools expose" in `perch/src/term/README.md` (line 200), is on this base (T2, merged at 82f677b), and its first three bullets are the three risks the line states. The line links nothing, and a source test pins it.
- The token: no line of this folder names it, and `auth()` (`core/api.js`) goes only into a request's headers (`headers: auth(...)`, the stream's header argument). A source-scan test pins both, so a URL, a log line or a DOM write cannot carry it unnoticed.
- A header's name is `headTitle(row)` (tab.js): the title, else the foreground, else the id, where a title or foreground that is spaces or controls only is no name (`titleText` trims after its cut).
- Reconnects wait at least `MIN_WAIT` (1 s), a quick one included. A resync reconnects quickly by design; a screen whose load fails under continuous output would otherwise reconnect in a loop. The growing wait (1 s, 2 s, ... 10 s) was already 1 s at its first step, so the floor changes only the quick path.
- A resync makes the entry `stale` until its reset arrives: `onFrame` stores no seq while stale, and the frames still in the aborted connection's read buffer reach no screen (the stream's callback checks the connection's abort signal). The reset frame clears `stale` and sets the seq again. The resync mark (`resyncing`) stays for the backlog guard and is cleared when the reset's bytes are parsed, as before. The two are separate on purpose: clearing the seq gate only at the parse would leave a window in which live output after the reset keeps no seq, and a drop in that window would resume past nothing and repeat the bytes already on the screen.
- A reset's seq is held while its chunks may still come: `resetting` stays set until a frame at another seq arrives. If the connection ends first (a drop, a resync, a stop), `endConnection` forgets the seq, so the next connection asks for a fresh reset and does not resume past the chunks the drop cut short.

## Not in this folder

- The keys of a terminal pane, copy and paste, the leave-site guard, the pane's menu: `terms/pane.js` and `terms/keys.js` (T4b).
- With the ⌨ tab closed the stream is closed as well (10 s after the last view), so the screens get no output; the roster is still polled every 5 s. On the next open the stream resumes each terminal from its last seq, or sends a reset when the perch no longer has those bytes.
- The 5 s poll makes no screen: it fills the roster only. A terminal it lists while the tab is closed has no screen and its bytes queue under the bound; the first mount of the tab makes a screen for each (the xterm module loads then, once). At most 16 screens exist, the perch's table. The cost of up to 16 live views is not measured in a browser (the spec's risk); a folded view is `visibility: hidden`, which costs layout but not paint.
