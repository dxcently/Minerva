# webui/term/graph

The inspector's graph tab. `app.js` lists `GraphTab` in `INSPECTOR`; it gets `{ s, sid }` like every tab. One line per file.

| file | does |
|---|---|
| `index.js` | `GraphTab`. Under the perch (`mode() === 'perch'`) it is `RunsPane`: the services line, the runs and `[ new run ]`, then the run shown (its drawing, status, path, budgets, cancel or abandon, steps) or, with none shown, `TurnGraph` from `turns.js`. Under a door it is `TurnGraph` alone. `[ turn graph ]` sets `picked` to `'turns'`: the turn graph then stays up even while a run is going (the list still says which run). The form's gate and its start are `R.formGate` and `R.startFromForm`, one line each, given no health. The tab opens with `R.openTab()` (services and list now, every 10 s while visible) and watches the shown run with `R.watch(rid)` (unwatched when it closes) |
| `runs.js` | the jev runs' state and asking, pure parts first: the poll intervals (`pollMs`: 1 s running, 5 s parked, none once ended; `HEALTH_MS` 10 s; `retryMs` after failed looks), the paths (`ridOk`, `graphOk`, `detailPath`, `logPath` with the `after` cursor, `graphPath`), `foldLog` (the cursor moves forward only, an overlapping or late answer adds nothing), the answers (`answerOk`, `answerPayload`: 0-based numbers as the park prompt prints them, the exact label when a number is another option's label, `STOP`), `parkGate`, the new-run form (`fieldsOf`, `argsOf`, `runGate`, and `formGate` / `startFromForm` as the page calls them: the form and the one shared browser, never the services or the decision log, so `[ run ]` is open in each decision-log state), `refusalOf`. The second half holds the signals (`health`, `runList`, `graphList`, `picked`, `model`, `acting`, `notice`, `form`, `chosen`) and the polls: `openTab` and `watch`/`unwatch`/`poke`, every periodic read through `hubPoll` (core/lane.js), every person's action through `hubPost` (all under `runs/`), never the lane (a source scan in tests/runs.test.mjs holds both). `graphDoc` (one graph file, by `hubGet`, cached per name and sha) is a one-off read, not a poll. A hidden page asks nothing. `picked` is null, `'turns'` or a run id |
| `view.js` | the run view's words and components. Words, pure and tested: `servicesParts` / `servicesText` (`jev ● up · jevlike <ckpt> (weights …) · openjev … · decision log off · browser ● up`; the two weights lines fold under `[ details ]`; a down service shows its start command as text; `decision log on: <path>`, `decision log off`, `decision log: unknown`, shown and never a gate), `rowLine`, `statusParts` (a cancel reads cancelled), `pathText`, `budgetParts`, `spendLine`. Components take their data as props: `Services`, `RunList`, `NewRun` (`[ run ]` greyed for the form, for a holder (with `[ abandon ]` for a parked one), or while an action is in flight), `RunView` (`[ cancel ]`, `[ abandon ]`). Every perch string goes through `clean` and is drawn as a text node |
| `steps.js` | `Steps({ rid, v, row })`, the run's steps at the foot of the run view: one frame per step, in order: the page's heading and url, when it began (`+` from the run's start) and how long it took; the arrival check (`heading X ≠ goal`, `entail 0.12 < 0.80`); the top 8 bars (ProbBars, whose footer `… N more` shows the rest: the wording renderers/jev.js draws, shared with W1's jev rows); jev's view (context.js, folded); the verdict (`top 0.41 ≥ floor 0.35 · margin 0.03 < 0.05 → asked a person`, or `picked by rule (label equals goal)`, `only one option`, `chooser unavailable: …`); each park as an inline ask (park.js); the action (`clicked "Nile River" → Nile — Wikipedia`). Then the end, from the last jev_mark (`arrived at "Nile" in 3 decisions, 1 asked`, `failed: <reason>` with the door's word when it said completed, `exhausted: out of …`, `stopped: …`, `cancelled: <reason>`). A run the perch ended while its journal still reads parked (`rowEnd`, from the row's state, when the journal has no end of its own): `cancelled: the run was cancelled while its tool was running` (the cancel lost the race to the program), `cancelled: the run was cancelled`, or `abandoned: no answer was sent at this park`. The last 8 frames are drawn; `[ all N steps ]` shows the rest. A run with no step (failed, cancelled or abandoned before its first jev_mark enter) draws its end line alone, under no frame; a run with neither a step nor an end draws nothing. Pure words, tested: `tookText`, `arrivalOf`, `verdictOf`, `actionOf`, `endOf`, `rowEnd`, `barsOf` |
| `park.js` | `ParkAsk`, a park as an inline ask under its step: the question and why, the numbered options (0-based, with p), a click selects one, `[ answer ]` sends it (runs.js `answerRun` with `answerPayload`) and `[ stop ]` sends `stop`. Only the park the run waits on is live; an answered one says what its answer did (`answered 0: Egypt`, `answered "banana": not one of the options, asked again`). Both buttons are off with the reason: eidolon's (`parkGate`: a journaled failure, a refused try, a child running) or the person's (nothing picked, an answer in flight, no text names the option). A park with no options has no answer to give: only stop acts. Every reason, title and label goes through `clean` (a reason up to 400 characters). Pure: `askGate`, `stopGate`, `answeredLine`, `optionsOf` |
| `context.js` | `JevView`, jev's view of a choice, folded under `[ jev's view ]`: the context as jevlike reads it (its first 192 bytes, `CUT` in jevrun.js) and each option cut to 32 bytes; options that tie after the cut are flagged `tie after the cut: margin 0`. Pure: `viewOf`, `contextLine`, `TIE` |
| `turns.js` | `TurnGraph({ s, sid })` (`sid` is passed like every tab's and not read), the chat's turn graph, drawn from the session it is handed and nothing else (no focused pane, no inspected chat, no hub call: the same under a door and the perch, and a pinned pane can host it). `itemsOf(s)` reads the session's rows (the signals read subscribe the render); `turnsOf(items, running)` cuts turns at each `settle` row and at each `stopped` sys row (a stop closes its turn, so the next message starts a new one; a line that is no turn of its own, a settle or a sys line, makes none; a model message does, with no user row too, so a turn resumed after a park or a trigger is `#n turn`, and a message with no words (thinking only) makes none; the trailing turn is current only while `running` is true, and a stopped turn is never running; in a turn that is not current, an open call reads `not finished` and an open ask is not lit, as the turn box reads `not settled`); `graphOf(turns)` gives the states, edges and marks `drawGraph` draws: a box per turn, per call and per ask. A turn's calls are one chain down from its box, an ask waits in that chain just under its call, the asks on no call and then the verdicts on no call follow as one chain from the turn's last box, and the next turn hangs off the last box of the turn, so a long chat is a column, not a fan (a test holds a three-turn chat within the inspector's 256 px at the default font). A verdict is written on its call (`bash · refused`) when core/state.js attached it (the only open call of that name, with no verdict yet, decided at arrival: gap 14), otherwise it is a box of its own; a refused or declined verdict on a call marks that call failed, whatever the call's own end; every string from a model, a tool or a page goes through `clean` (renderers/jev.js) and is drawn as a text node; the newest `TURN_CAP` (20) turns are drawn, and the newest `CALL_CAP` (10) calls, asks and verdicts of each turn, the rest one box each (the tooltip says how many); `captionOf` is the line above. Paths never hold a dot (draw.js reads one as nesting) |
| `jevrun.js` | the run model, pure: `newRun` / `feed` (records or ndjson, `id <= lastId` skipped) / `view` / `reduce` turn `eidolon log --json` records (and the run's own `jev_graph` pages) into decision steps (menus with probs and best, rule and single picks, parks with their answer, escalations), the status (a failed final under a completed run is `failed`; a step with no result is `open`, which the perch's run state decides), `unresumable` with eidolon's sentence, budgets, and `drawing` + `marks` for `drawGraph`; no DOM, no fetch; one run per reducer |
| `project.js` | `project(doc or jsonText)`: a jev graph's JSON -> the drawing the `jev_graph` tool answers ({ graph, initial, states, edges, marks, ... }), mirroring the vendored `jev/tools/graph.rn` function for function |
| `draw.js` | `layout(states, edges, opts)` (boxes, frames and right-angled lines under vendored dagre, pure) and `drawGraph(graph, marks)` (the SVG vnode; marks: current, visited, final, failed) |
| `graph.css` | the tab's styles, linked from `index.html`: the runs' text (`.grun`: the services line, the list, the new-run form, the run's lines) and the drawn graph's boxes, frames, lines and marks |
